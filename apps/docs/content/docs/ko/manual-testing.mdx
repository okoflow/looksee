description: 로컬 비디오 파일을 사용한 엔드투엔드 스모크 테스트.
---

이 스모크 테스트는 로컬 비디오 파일을 사용해 MediaMTX, ONNX 추론, Valkey 메시징, API 그래프 실행,
WebSocket 업데이트, PostgreSQL 알림, WHEP 재생을 검증합니다.

## 사전 요구 사항

- 루트 [빠른 시작](https://github.com/okoflow/looksee#run-with-docker)의 Docker 스택.
- `GET /models`에 나열되는 호환 모델 번들.
- 화면에 보이는 객체가 해당 모델의 레이블과 일치하는 비디오.

명령은 저장소 루트에서 실행하세요.

## 테스트 비디오 추가

에디터를 통해 H.264 호환 비디오 또는 FFmpeg로 읽을 수 있는 비디오를 업로드하세요. Camera
노드의 소스를 **File**로 설정하고 Video library 대화 상자에서 **Upload video**를 선택합니다.
API는 파일을 자산 저장소에 저장한 뒤, MediaMTX가 읽기 전용으로 마운트하는 공유 미디어
볼륨에 캐시합니다.

`file` 카메라 소스는 온디맨드 FFmpeg 퍼블리셔를 시작해 캐시된 비디오를 반복 재생하고, 이를
카메라의 RTSP 및 WHEP 경로로 노출합니다.

## 워크플로 생성

1. [웹 인터페이스](http://localhost:3000)를 여세요. 새로 설치한 경우 설정 화면에서 소유자
   계정을 생성하라는 안내가 표시되며, 이후 해당 계정으로 로그인하세요.
2. **New workflow**를 선택하세요.
3. **Blank workflow**를 선택하고 이름을 입력한 뒤 생성하세요.
4. 캔버스에 Camera, Detect, Alert 노드를 추가하세요.
5. `Camera → Detect → Alert` 순서로 연결하세요.
6. Camera의 소스를 **File**로 설정하고 Video library에서 업로드한 비디오를 선택하세요.
7. Detect에 설치된 모델을 설정하세요. Events를 비워 두면 매니페스트가 노출하는 모든
   이벤트가 전달됩니다.
8. Alert의 심각도를 `warning`으로 유지한 뒤 **Save**를 선택하세요.
9. **Run**을 선택하세요.

추론 서비스가 첫 프레임을 수신하면 워크플로가 `pending`에서 `active`로 전환됩니다. **Live**
패널을 열어 WHEP 재생, 바운딩 박스, 파생 이벤트를 확인하세요. **Alerts**를 열어 일치하는
탐지가 영구 알림 행을 생성하는지 확인하세요.

## 서비스 확인

```bash
docker compose ps
curl --fail --silent http://localhost:8000/health
docker compose logs --tail=200 api inference mediamtx
```

기대 결과:

- `/health`가 `{"status":"ok"}`를 반환합니다.
- Detect 노드의 모델 선택기에 설치된 모델이 나열됩니다(`/models` API는 로그인된 세션이
  필요합니다).
- 추론 로그에 모델 어댑터와 실행 공급자가 표시됩니다.
- API 로그에 그래프, 프레임, 액션 오류가 없습니다.
- 워크플로가 실행되는 동안 MediaMTX가 카메라 경로를 준비 상태로 보고합니다.

## 필터와 스냅샷 추가

최소 그래프가 동작한 뒤에는 다음을 진행하세요.

1. 워크플로를 중지하세요.
2. Detect와 Alert 사이에 필터를 하나 삽입하세요. 필요한 폴리곤이나 라인을 설정합니다.
3. 이미지 증거가 필요하면 Alert 앞에 Snapshot을 삽입하세요.
4. 워크플로를 저장하고 다시 실행하세요.

Snapshot이 성공하면 알림 페이로드에 `snapshot_url`이 포함됩니다. 이 URL은 API의
`/snapshots/` 경로에서 제공되며, 이미지는 `api_snapshots` 볼륨에 보존됩니다.

## 자주 발생하는 문제 진단

| 증상 | 확인 사항 |
| --- | --- |
| 선택기에 모델이 없음 | 번들 파일 두 개가 모두 있는지 확인하고 API 로그에서 매니페스트 검증 오류를 살펴보세요 |
| 실행 시 HTTP `422` 반환 | 반환된 `node_id`를 활용해 포커스된 노드를 설정하거나 그래프 토폴로지를 수정하세요 |
| 카메라 상태가 `error`로 변경됨 | 자산 업로드, FFmpeg 디코딩, 선택한 모델 시그니처, 추론 로그를 확인하세요 |
| 비디오는 재생되지만 박스가 없음 | 모델이 샘플 속 객체를 탐지하는지 확인하고, 필요하면 신뢰도 임계값을 낮추세요 |
| 박스는 표시되지만 이벤트가 없음 | 매니페스트 이벤트 매핑과 Detect의 이벤트 선택을 확인하세요 |
| 알림이 표시되지 않음 | 필터 분기를 확인하고 Detect에서 Alert 노드에 도달할 수 있는지 확인하세요 |
| 스냅샷이 없음 | Snapshot을 Alert 업스트림에 배치하고 API 스냅샷 디렉터리와 마지막 프레임 TTL을 확인하세요 |
| WHEP 재생 실패 | `WEBRTC_HOST_IP`, MediaMTX 자격 증명, 공개된 WebRTC 포트를 확인하세요 |

## 테스트 중지

워크플로 에디터에서 **Stop**을 선택한 뒤, 작업이 끝나면 로컬 스택을 중지하세요:

```bash
docker compose down
```
