---
title: Локальное тестирование воркфлоу
description: Сквозной смоук-тест с локальным видеофайлом.
---

Этот смоук-тест проверяет MediaMTX, ONNX-инференс, обмен сообщениями через Valkey, выполнение
графа в API, обновления по WebSocket, алерты в PostgreSQL и воспроизведение по WHEP с
использованием локального видеофайла.

## Предварительные требования

- Docker-стек из корневого [быстрого старта](https://github.com/okoflow/looksee#run-with-docker).
- Совместимый бандл модели, который отображается в ответе `GET /models`.
- Видео, на котором видимые объекты соответствуют меткам этой модели.

Выполняйте команды из корня репозитория.

## Добавьте тестовое видео

Загрузите через редактор видео, совместимое с H.264 или читаемое FFmpeg: настройте ноду Camera
с источником **File** и выберите **Upload video** в диалоге Video library. API сохраняет файл
в хранилище ассетов и кэширует его в общий том медиафайлов, который MediaMTX монтирует в
режиме только для чтения.

Источник камеры `file` запускает FFmpeg-паблишер по требованию, который зацикливает
кэшированное видео и публикует его как RTSP- и WHEP-путь камеры.

## Создайте воркфлоу

1. Откройте [веб-интерфейс](http://localhost:3000). При первой установке экран настройки
   попросит создать аккаунт владельца; после этого войдите под ним.
2. Выберите **New workflow**.
3. Выберите **Blank workflow**, введите имя и создайте воркфлоу.
4. Добавьте на холст ноды Camera, Detect и Alert.
5. Соедините `Camera → Detect → Alert`.
6. Настройте Camera с источником **File** и выберите загруженное видео из Video
   library.
7. Настройте Detect с установленной моделью. Оставьте Events пустым, чтобы пропускать
   все события, объявленные в манифесте.
8. Оставьте у Alert серьёзность `warning`, затем выберите **Save**.
9. Выберите **Run**.

Воркфлоу переходит из `pending` в `active` после того, как инференс получит первый кадр.
Откройте панель **Live**, чтобы увидеть воспроизведение по WHEP, ограничивающие рамки и
производные события. Откройте **Alerts**, чтобы убедиться, что подходящие детекции создают
долговременные записи алертов.

## Проверьте сервисы

```bash
docker compose ps
curl --fail --silent http://localhost:8000/health
docker compose logs --tail=200 api inference mediamtx
```

Ожидаемые результаты:

- `/health` возвращает `{"status":"ok"}`.
- Селектор модели в ноде Detect показывает установленную модель (API `/models` требует
  сессии с выполненным входом).
- Логи инференса показывают адаптер модели и execution provider.
- Логи API не содержат ошибок графа, кадров или действий.
- MediaMTX сообщает, что путь камеры готов, пока воркфлоу выполняется.

## Добавьте фильтры и снапшоты

После того как минимальный граф заработает:

1. Остановите воркфлоу.
2. Вставьте один фильтр между Detect и Alert. Настройте требуемый полигон или линию.
3. Вставьте Snapshot перед Alert, если нужны изображения в качестве доказательства.
4. Сохраните и снова запустите воркфлоу.

Полезная нагрузка алерта содержит `snapshot_url` после успешного выполнения Snapshot. URL
раздаётся API по пути `/snapshots/`, а изображение сохраняется в томе `api_snapshots`.

## Диагностируйте типичные сбои

| Симптом | Что проверить |
| --- | --- |
| В селекторе нет моделей | Убедитесь, что присутствуют оба файла бандла, и проверьте логи API на ошибки валидации манифеста |
| Запуск возвращает HTTP `422` | Используйте возвращённый `node_id`; настройте выделенную ноду или исправьте топологию графа |
| Статус камеры становится `error` | Проверьте загрузку ассета, декодирование FFmpeg, сигнатуру выбранной модели и логи инференса |
| Видео воспроизводится без рамок | Убедитесь, что модель обнаруживает объекты на образце, и при необходимости понизьте порог уверенности |
| Рамки появляются без событий | Проверьте сопоставления событий в манифесте и выбор событий в ноде Detect |
| Алерты не появляются | Проверьте ветви фильтров и убедитесь, что нода Alert достижима из Detect |
| Снапшот отсутствует | Разместите Snapshot выше по потоку от Alert и проверьте каталог снапшотов API и TTL последнего кадра |
| Воспроизведение по WHEP не работает | Проверьте `WEBRTC_HOST_IP`, учётные данные MediaMTX и опубликованные порты WebRTC |

## Остановите тест

Выберите **Stop** в редакторе воркфлоу, затем по завершении остановите локальный стек:

```bash
docker compose down
```
