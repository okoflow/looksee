Воркфлоу — это ориентированный граф из источников камер, детекции, фильтров и действий.
Черновики хранятся в PostgreSQL, а API проверяет требования времени выполнения, прежде
чем воркфлоу будет включён.

## Правила графа

Все сохранённые графы должны иметь уникальные идентификаторы нод и рёбер, корректные
конечные точки рёбер и метаданные ветки только на рёбрах, выходящих из фильтров.
Черновик может содержать незавершённые или несвязанные ноды.

Каждый включаемый путь от источника должен удовлетворять этим правилам:

- Достижимый граф ацикличен.
- Источник достигает ровно одной ноды «Detect».
- Выбранная модель существует и поддерживает настроенные события и классы.
- У каждой достижимой ноды заданы все обязательные значения времени выполнения.

Каждый фильтр направляет совпадение на рёбра `if`, а несовпадение — на рёбра `else`.
Исходящее ребро фильтра без метки ведёт себя как `if`.

## Источники камер

MediaMTX нормализует каждый источник в один путь с именем в виде UUID для инференса и
воспроизведения в браузере.

| Источник | Конфигурация |
| --- | --- |
| RTSP | URL исходного потока `rtsp://` или `rtsps://` |
| RTMP | URL исходного потока `rtmp://` или `rtmps://` |
| SRT | URL исходного потока `srt://` |
| WHEP | Удалённый эндпоинт `http://`, `https://`, `whep://` или `wheps://` |
| WebRTC | Без URL; запустите воркфлоу, затем опубликуйте веб-камеру браузера через WHIP |
| File | Относительный путь внутри `MEDIA_DIR`; MediaMTX зацикливает его через FFmpeg |

Пути к файлам могут содержать буквы, цифры, `.`, `_`, `-` и `/`. Они не могут содержать
пробелы, скрытые сегменты пути, `..` и символы командной оболочки.

## Детекция

В ноде «Detect» выбираются:

- Модель из каталога рантайма.
- Виды событий, которые пропускаются дальше; при пустом выборе пропускаются все события, предоставляемые моделью.
- Порог уверенности от 0 до 1.
- Частота инференса от 1 до 15 проверок в секунду.

В настоящее время один источник камеры поддерживает одну достижимую ноду «Detect».
Правила для бандлов и событий см. в [каталоге моделей](./model-catalog.mdx).

## Фильтры

| Нода | Условие совпадения |
| --- | --- |
| If / Else | Вид события, класс объекта, количество детекций или максимальная уверенность удовлетворяет типизированному сравнению |
| Zone | Центр хотя бы одной детекции лежит внутри полигона |
| Class | Метка хотя бы одной детекции принадлежит выбранным классам |
| Debounce | Нода не пропускала событие в течение своего кулдауна |
| Schedule | Время события попадает в выбранные часы и дни недели, а при инверсии — вне их |
| Line crossing | Отслеживаемый объект пересекает линию из двух точек в выбранном направлении |
| Dwell | Отслеживаемый объект остаётся внутри полигона в течение заданной длительности |
| Count | Количество детекций в необязательном полигоне больше либо равно порогу или меньше либо равно ему |
| Size | Площадь хотя бы одной ограничивающей рамки попадает в заданный диапазон долей кадра |

Нодам «Zone» и «Dwell» нужны полигоны, прежде чем воркфлоу сможет запуститься. Ноде
«Line crossing» нужны две точки. Пустой полигон «Count» означает весь кадр.

При вычислении «Schedule» используется `EVENT_TIMEZONE`. Состояние «Debounce»,
«Line crossing», «Dwell» и глобального кулдауна событий находится в процессе API и
сбрасывается при его перезапуске или начале нового запуска.

## Действия

| Нода | Поведение | Требует |
| --- | --- | --- |
| Alert | Сохраняет алерт уровня `info`, `warning` или `critical` | Нет |
| Snapshot | Сохраняет последний JPEG, при необходимости с рамками, и добавляет его в контекст последующих нод | Нет |
| Telegram | Отправляет текст или фото снапшота | Учётные данные Telegram-бота |
| Webhook | Отправляет полезную нагрузку события методом `GET`, `POST` или `PUT` | Нет |
| Email | Отправляет сообщение по шаблону и необязательное JPEG-вложение | Учётные данные SMTP |
| MQTT | Публикует шаблон либо JSON-нагрузку по умолчанию | Учётные данные MQTT |
| Discord | Отправляет событие в канал через вебхук | Учётные данные вебхука Discord |

Секреты интеграций хранятся на странице учётных данных в зашифрованном виде; нода
ссылается на учётные данные по id, а при включении воркфлоу проверяется, что ссылка
разрешается.

Размещайте «Snapshot» перед действиями-уведомлениями, которым нужен `snapshot_url` или
вложение. Шаблоны поддерживают `{kind}`, `{camera_id}`, `{ts}`, `{count}` и
`{snapshot_url}`. Недопустимые плейсхолдеры логируются, а исходный шаблон доставляется
без изменений.

Сбой действия логируется и не препятствует выполнению последующих нод.

## Пресеты

Диалог создания предлагает пустой воркфлоу и восемь текущих пресетов:

- Проникновение в нерабочие часы
- Подсчёт людей
- Праздношатание
- Занятость парковки
- Мониторинг очереди
- Контроль ношения касок
- Огонь и дым
- Свободные парковочные места

Пресеты создают редактируемые черновики, а не готовые к запуску развёртывания. Каждый
пресет оставляет модель невыбранной. Перед запуском настройте камеру, модель,
обязательные зоны или линии, а также адресатов внешних действий.

Пресеты «Контроль ношения касок», «Огонь и дым» и «Свободные парковочные места»
предзаполняют семантические виды событий. Выбранная модель должна предоставлять эти
виды. Остальные пресеты оставляют выбор событий пустым, чтобы вы могли выбрать события
установленной модели.
