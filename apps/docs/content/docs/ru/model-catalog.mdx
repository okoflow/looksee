LookSee обнаруживает ONNX-модели в файловой системе среды выполнения. API использует
каталог для редактирования и валидации воркфлоу; инференс использует тот же бандл, чтобы
загрузить метки и создать сессию ONNX.

## Структура бандла

Каждой модели соответствует одна директория внутри `MODELS_DIR`:

```text
models/
└── <model-id>/
    ├── model.onnx
    └── manifest.json
```

Оба файла обязательны. API игнорирует неполные или некорректные бандлы и записывает
причину в лог. Идентификатор модели — это имя директории; он должен:

- Содержать только строчные буквы ASCII, цифры, `_` или `-`.
- Иметь длину от 1 до 64 символов.
- Оставаться неизменным после обнаружения модели.

При изменении весов, меток или метаданных используйте новый идентификатор, например
`dfine-m-fire-v2`. API и инференс кэшируют обнаруженный идентификатор на всё время жизни
своих процессов; замена файлов на месте не гарантирует обновления активных сессий.

Файлы моделей игнорируются Git и монтируются в контейнеры API и инференса в режиме
только для чтения.

## Схема манифеста

```json
{
  "name": "D-FINE-M Fire and Smoke",
  "labels": ["fire", "other", "smoke"],
  "recommended_confidence_threshold": 0.3,
  "events": {
    "fire": "FIRE_DETECTED",
    "other": null
  }
}
```

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `labels` | Да | Сопоставление идентификаторов классов уникальным непустым меткам |
| `name` | Нет | Отображаемое имя; иначе выводится из идентификатора модели |
| `recommended_confidence_threshold` | Нет | Значение от 0 до 1, применяемое при выборе модели в редакторе |
| `events` | Нет | Переопределение события для метки; `null` подавляет эту метку |

Неизвестные поля отклоняются. Каждый ключ в `events` должен присутствовать в `labels`.

`labels` может быть упорядоченным массивом, где индекс массива — это идентификатор
класса, либо JSON-объектом с последовательными целочисленными ключами начиная с нуля:

```json
{
  "labels": {
    "0": "fire",
    "1": "other",
    "2": "smoke"
  }
}
```

Метки классов должны быть уникальными. Инференс сообщает об ошибке, если модель выдаёт
идентификатор класса, отсутствующий в манифесте.

## Сопоставление событий

API преобразует каждую обнаруженную метку в семантическое событие воркфлоу:

1. Если метка есть в `events`, используется заданное для неё значение.
2. Если заданное значение — `null`, событие для этой метки не создаётся.
3. Иначе метка переводится в верхний регистр, последовательности небуквенно-цифровых
   символов заменяются на `_`, и при необходимости добавляется `_DETECTED`.

Например, `space-occupied` превращается в `SPACE_OCCUPIED_DETECTED`. Виды событий должны
начинаться с заглавной буквы, содержать только заглавные буквы, цифры и подчёркивания и
быть не длиннее 64 символов.

Ответ `GET /models` содержит итоговое отображаемое имя, классы, виды событий и
рекомендуемый порог. Веб-приложение обновляет этот каталог, пока оно открыто, поэтому
новый идентификатор модели может появиться без пересборки фронтенда.

## Поддерживаемые сигнатуры ONNX

Инференс выбирает адаптер по именам, типам и рангам входных и выходных тензоров. Он
никогда не ветвится по идентификатору модели. Текущий реестр поддерживает два контракта
D-FINE.

### Deploy-экспорт D-FINE

```text
inputs
  images             float tensor, rank 4, three channels, static square size
  orig_target_sizes  int64 tensor, rank 2, final dimension 2

outputs
  labels             int64 tensor, rank 2
  boxes              float tensor, rank 3, final dimension 4
  scores             float tensor, rank 2
```

Адаптер сохраняет соотношение сторон с помощью центрированных чёрных полей (letterbox),
работает с уже декодированным выводом XYXY и переводит рамки обратно в пиксели исходного
кадра.

### Raw-экспорт D-FINE

```text
input
  one float tensor   rank 4, three channels, static square size

outputs
  logits             float tensor, rank 3
  pred_boxes         float tensor, rank 3, final dimension 4
```

Адаптер масштабирует кадр, применяет сигмоиду для получения оценок, выбирает лучший
класс для каждого запроса (query) и преобразует нормализованные рамки CXCYWH в
пиксельные рамки XYXY в координатах исходного кадра.

Каталог проверяет только директорию и манифест. Инференс проверяет сигнатуру ONNX, когда
воркфлоу впервые запрашивает модель. Неподдерживаемая или неоднозначная сигнатура
переводит воркер этой камеры в состояние ошибки, а сама сигнатура записывается в логи
инференса.

## Поведение во время выполнения

- Узел детекции задаёт `model_id`, порог уверенности (confidence), виды событий и число
  проверок в секунду.
- Разные камеры могут одновременно использовать разные модели.
- Камеры с одинаковым идентификатором модели совместно используют одну лениво
  загружаемую сессию ONNX на каждый процесс инференса.
- Приоритет провайдеров: CUDA, если установленный рантайм её предоставляет, затем CPU.
- Изменение модели, уверенности, числа проверок в секунду или источника начинает новый
  запуск с фенсингом (fenced run).
- Удаление бандла не вытесняет уже закэшированную модель. Выводя идентификатор из
  эксплуатации, остановите зависимые воркфлоу и перезапустите сервисы.

## Добавление адаптера архитектуры

1. Добавьте `OnnxDetectionAdapter` в
   `apps/inference/src/inference/adapters/onnx/models/`.
2. Сопоставьте полный контракт тензоров в `supports(signature)`.
3. Преобразуйте вывод в `supervision.Detections` с рамками XYXY в пикселях, значениями
   уверенности и идентификаторами классов.
4. Зарегистрируйте тип в `apps/inference/src/inference/adapters/onnx/registry.py`.
5. Сохраняйте предикат специфичным для архитектуры и независимым от идентификатора
   модели.

Команды запуска смотрите в [руководстве по сервису инференса](https://github.com/okoflow/looksee/blob/main/apps/inference/README.md).
