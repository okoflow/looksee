בדיקת עשן (smoke test) זו מפעילה את MediaMTX, את ההסקה (inference) של ONNX, את העברת
ההודעות ב-Valkey, את הרצת הגרף ב-API, את עדכוני ה-WebSocket, את ההתראות ב-PostgreSQL
ואת ניגון ה-WHEP — עם קובץ וידאו מקומי.

## דרישות מקדימות

- מחסנית ה-Docker מתוך [מדריך ההתחלה המהירה](https://github.com/okoflow/looksee#run-with-docker) שבשורש המאגר.
- חבילת מודל תואמת שמופיעה ברשימה של `GET /models`.
- וידאו שהאובייקטים הנראים בו תואמים לתוויות של אותו מודל.

הריצו את הפקודות משורש המאגר.

## הוספת וידאו לבדיקה

העלו דרך העורך וידאו תואם H.264 או וידאו ש-FFmpeg יודע לקרוא: הגדירו צומת Camera
עם מקור **File** ובחרו **Upload video** בחלון הדו-שיח Video library. ה-API שומר את
הקובץ במאגר הנכסים (asset store) ומטמין אותו ב-volume המדיה המשותף ש-MediaMTX מעגן
לקריאה בלבד.

מקור מצלמה מסוג `file` מפעיל לפי דרישה publisher של FFmpeg, שמנגן בלולאה את הווידאו
שהוטמן וחושף אותו כנתיב ה-RTSP וה-WHEP של המצלמה.

## יצירת תהליך העבודה

1. פתחו את [ממשק הווב](http://localhost:3000). בהתקנה נקייה מסך ההגדרה הראשונית
   מבקש מכם ליצור את חשבון הבעלים; לאחר מכן היכנסו איתו.
2. בחרו **New workflow**.
3. בחרו **Blank workflow**, הזינו שם וצרו אותו.
4. הוסיפו לקנבס צמתים מסוג Camera, Detect ו-Alert.
5. חברו `Camera → Detect → Alert`.
6. הגדירו את Camera עם מקור **File** ובחרו את הווידאו שהעליתם מתוך Video library.
7. הגדירו את Detect עם המודל המותקן. השאירו את Events ריק כדי להעביר כל אירוע
   שהמניפסט חושף.
8. השאירו את Alert ברמת החומרה `warning`, ואז בחרו **Save**.
9. בחרו **Run**.

תהליך העבודה עובר מ-`pending` ל-`active` לאחר ששירות ה-inference מקבל את הפריים
הראשון שלו. פתחו את החלונית **Live** כדי לראות ניגון WHEP, תיבות תוחמות
(bounding boxes) ואירועים נגזרים. פתחו את **Alerts** כדי לוודא שזיהויים תואמים
יוצרים שורות התראה עמידות.

## אימות השירותים

```bash
docker compose ps
curl --fail --silent http://localhost:8000/health
docker compose logs --tail=200 api inference mediamtx
```

תוצאות צפויות:

- `/health` מחזיר `{"status":"ok"}`.
- בורר המודלים של צומת Detect מציג את המודל המותקן (ה-API של `/models` מחייב סשן
  מחובר).
- הלוגים של inference מציגים את מתאם המודל ואת ספק ההרצה (execution provider).
- הלוגים של ה-API אינם מכילים שגיאות גרף, פריים או פעולה.
- MediaMTX מדווח שנתיב המצלמה מוכן כל עוד תהליך העבודה רץ.

## הוספת מסננים ותמונות מצב

לאחר שהגרף המינימלי עובד:

1. עצרו את תהליך העבודה.
2. הוסיפו מסנן אחד בין Detect ל-Alert. הגדירו פוליגון או קו לפי הצורך.
3. הוסיפו Snapshot לפני Alert אם אתם רוצים תיעוד מצולם.
4. שמרו והריצו את תהליך העבודה שוב.

מטען ההתראה (payload) מכיל `snapshot_url` לאחר ש-Snapshot מצליח. כתובת ה-URL מוגשת
מה-API תחת `/snapshots/`, והתמונה נשמרת ב-volume בשם `api_snapshots`.

## אבחון כשלים נפוצים

| תסמין | בדיקה |
| --- | --- |
| אין מודלים בבורר | ודאו ששני קובצי החבילה קיימים וחפשו בלוגים של ה-API שגיאות אימות של המניפסט |
| הפעלת Run מחזירה HTTP `422` | היעזרו ב-`node_id` שהוחזר; הגדירו את הצומת שמקבל פוקוס או תקנו את טופולוגיית הגרף |
| סטטוס המצלמה הופך ל-`error` | בדקו את העלאת הנכס, את הפענוח ב-FFmpeg, את חתימת המודל שנבחר ואת הלוגים של inference |
| הווידאו מתנגן ללא תיבות | ודאו שהמודל מזהה אובייקטים בדוגמה, ובמידת הצורך הורידו את סף הביטחון |
| תיבות מופיעות ללא אירועים | בדקו את מיפויי האירועים במניפסט ואת בחירת האירועים בצומת Detect |
| התראות אינן מופיעות | בדקו את ענפי המסננים וודאו שצומת Alert נגיש מ-Detect |
| תמונת המצב חסרה | מקמו את Snapshot במעלה הזרם של Alert ובדקו את ספריית תמונות המצב של ה-API ואת ה-TTL של הפריים האחרון |
| ניגון WHEP נכשל | בדקו את `WEBRTC_HOST_IP`, את פרטי הגישה של MediaMTX ואת פורטי ה-WebRTC המפורסמים |

## עצירת הבדיקה

בחרו **Stop** בעורך תהליכי העבודה, ובסיום עצרו את המחסנית המקומית:

```bash
docker compose down
```
