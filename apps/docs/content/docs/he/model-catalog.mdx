LookSee מגלה מודלי ONNX ממערכת הקבצים בזמן ריצה. ה-API משתמש בקטלוג לעריכה
ולאימות של תהליכי עבודה; שירות ההסקה (inference) משתמש באותה חבילת מודל כדי
לטעון את התוויות וליצור את סשן ה-ONNX.

## מבנה חבילת המודל

לכל מודל יש תיקייה אחת תחת `MODELS_DIR`:

```text
models/
└── <model-id>/
    ├── model.onnx
    └── manifest.json
```

שני הקבצים נדרשים. ה-API מתעלם מחבילות חלקיות או לא תקינות ורושם את הסיבה
ביומן. מזהה המודל הוא שם התיקייה, והוא חייב:

- להכיל אך ורק אותיות ASCII קטנות, ספרות, `_` או `-`.
- להכיל בין 1 ל-64 תווים.
- להישאר ללא שינוי לאחר שהמודל התגלה.

השתמשו במזהה חדש כאשר המשקולות, התוויות או המטא-נתונים משתנים, למשל
`dfine-m-fire-v2`. ה-API ושירות ההסקה שומרים במטמון מזהה שהתגלה למשך כל חיי
התהליכים שלהם; החלפת קבצים במקומם אינה מעדכנת סשנים פעילים באופן אמין.

קבצי המודל מוחרגים מ-Git ומחוברים (mounted) במצב קריאה בלבד לקונטיינרים של
ה-API ושל ההסקה.

## סכמת המניפסט

```json
{
  "name": "D-FINE-M Fire and Smoke",
  "labels": ["fire", "other", "smoke"],
  "recommended_confidence_threshold": 0.3,
  "events": {
    "fire": "FIRE_DETECTED",
    "other": null
  }
}
```

| שדה | נדרש | משמעות |
| --- | --- | --- |
| `labels` | כן | מיפוי ממזהה מחלקה לתווית ייחודית ולא ריקה |
| `name` | לא | שם תצוגה; אחרת נגזר ממזהה המודל |
| `recommended_confidence_threshold` | לא | ערך בין 0 ל-1 המוחל כאשר המודל נבחר בעורך |
| `events` | לא | דריסת המיפוי מתווית לאירוע; `null` משתיק את התווית |

שדות לא מוכרים נדחים. כל מפתח ב-`events` חייב להתקיים ב-`labels`.

`labels` יכול להיות מערך סדור, שבו אינדקס המערך הוא מזהה המחלקה, או אובייקט
JSON עם מפתחות שלמים רציפים המתחילים מאפס:

```json
{
  "labels": {
    "0": "fire",
    "1": "other",
    "2": "smoke"
  }
}
```

התוויות חייבות להיות ייחודיות. שירות ההסקה מדווח על שגיאה אם המודל פולט מזהה
מחלקה שאינו קיים במניפסט.

## מיפוי אירועים

ה-API ממיר כל תווית שזוהתה לאירוע סמנטי בתהליך העבודה:

1. אם `events` מכיל את התווית, נעשה שימוש בערך שהוגדר עבורה.
2. אם הערך שהוגדר הוא `null`, לא נוצר אירוע עבור אותה תווית.
3. אחרת, התווית מומרת לאותיות גדולות, רצפים שאינם אלפאנומריים מוחלפים ב-`_`,
   ובמידת הצורך מתווספת הסיומת `_DETECTED`.

לדוגמה, `space-occupied` הופך ל-`SPACE_OCCUPIED_DETECTED`. סוגי אירועים חייבים
להתחיל באות גדולה, להכיל אך ורק אותיות גדולות, ספרות וקווים תחתונים, ולהיות
באורך של עד 64 תווים.

התגובה של `GET /models` חושפת את שם התצוגה שנקבע, את המחלקות, את סוגי האירועים
ואת הסף המומלץ. אפליקציית הווב מרעננת את הקטלוג כל עוד היא פתוחה, כך שמזהה מודל
חדש יכול להופיע ללא בנייה מחדש של צד הלקוח (frontend).

## חתימות ONNX נתמכות

שירות ההסקה בוחר מתאם לפי השמות, הטיפוסים והדרגות (rank) של טנזורי הקלט והפלט.
הוא לעולם אינו מסתעף לפי מזהה מודל. הרישום (registry) הנוכחי תומך בשני חוזים
של D-FINE.

### ייצוא deploy של D-FINE

```text
inputs
  images             float tensor, rank 4, three channels, static square size
  orig_target_sizes  int64 tensor, rank 2, final dimension 2

outputs
  labels             int64 tensor, rank 2
  boxes              float tensor, rank 3, final dimension 4
  scores             float tensor, rank 2
```

המתאם שומר על יחס הממדים באמצעות letterbox שחור ממורכז, עובד עם פלט XYXY
מפוענח, וממפה את התיבות בחזרה לפיקסלים של הפריים המקורי.

### ייצוא raw של D-FINE

```text
input
  one float tensor   rank 4, three channels, static square size

outputs
  logits             float tensor, rank 3
  pred_boxes         float tensor, rank 3, final dimension 4
```

המתאם משנה את גודל הפריים, מחיל sigmoid על הציונים, בוחר את המחלקה הטובה ביותר
לכל query, וממיר תיבות CXCYWH מנורמלות לתיבות XYXY בפיקסלים של הפריים המקורי.

הקטלוג מאמת רק את התיקייה ואת המניפסט. שירות ההסקה מאמת את חתימת ה-ONNX כאשר
תהליך עבודה מבקש את המודל בפעם הראשונה. חתימה לא נתמכת או דו-משמעית מעבירה את
ה-worker של אותה מצלמה למצב שגיאה ורושמת את החתימה ביומני ההסקה.

## התנהגות בזמן ריצה

- צומת זיהוי (detect) בוחר `model_id`, סף ביטחון (confidence), סוגי אירועים
  ומספר בדיקות לשנייה.
- מצלמות שונות יכולות להשתמש במודלים שונים במקביל.
- מצלמות המשתמשות באותו מזהה מודל חולקות סשן ONNX אחד, בטעינה עצלה, לכל תהליך
  הסקה.
- סדר העדיפות בין ספקי ההרצה (execution providers) הוא CUDA, כאשר סביבת הריצה
  המותקנת חושפת אותו, ולאחר מכן CPU.
- שינוי מודל, סף ביטחון, מספר בדיקות לשנייה או מקור מתחיל ריצה מגודרת (fenced)
  חדשה.
- הסרת חבילה אינה מפנה מהמטמון מודל שכבר נטען אליו. עצרו תהליכי עבודה תלויים
  והפעילו מחדש את השירותים כאשר מוציאים מזהה משימוש.

## הוספת מתאם ארכיטקטורה

1. הוסיפו `OnnxDetectionAdapter` תחת
   `apps/inference/src/inference/adapters/onnx/models/`.
2. התאימו את חוזה הטנזורים המלא ב-`supports(signature)`.
3. המירו את הפלט ל-`supervision.Detections` עם תיבות XYXY בפיקסלים, ערכי
   ביטחון ומזהי מחלקות.
4. רשמו את הטיפוס ב-`apps/inference/src/inference/adapters/onnx/registry.py`.
5. שמרו על פרדיקט ספציפי לארכיטקטורה ובלתי תלוי במזהה המודל.

לפקודות זמן הריצה, ראו את [מדריך שירות ההסקה](https://github.com/okoflow/looksee/blob/main/apps/inference/README.md).
