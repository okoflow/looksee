## Versioning

LookSee follows [Semantic Versioning](https://semver.org), and one number covers the
whole stack — the api, the inference service, the studio and this documentation site
are released together.

The project is still on its `0.x` line: there has been no public release yet, so a
minor version may still change behaviour an operator depends on. `1.0.0` lands with
the first public release. From there:

- **Major** — the upgrade needs a hand: a migration that cannot be rolled back, a
  renamed or removed environment variable, a workflow schema that existing graphs no
  longer satisfy, or a route that is gone. Every such release spells out what to do
  under **Breaking**.
- **Minor** — new features, node kinds, model architectures and documentation.
- **Patch** — fixes and dependency updates.

A refactor an operator cannot observe changes nothing about compatibility, so it never
takes a major.
